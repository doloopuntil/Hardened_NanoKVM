# System 1.0.0 with application 3.0.0

The system moves from the vendor's Linux 5.10 to mainline Linux 6.18 LTS (6.18.29), with
the boot firmware, kernel and media drivers built from source. It includes everything in
[0.4.0](0.4.0.md), which was never published on its own. The
[migration plan](../development/kernel-6x-migration-plan.md) has the details and the
measurements behind each change.

## Getting it

There are no published release assets or update channels for 1.0.0 yet. Build the image
with the [CI image build](../development/ci-image-build.md) and flash it
([Install](../guide/install.md)). A device on a 5.10 system (0.3.x or 0.4.0) moves to 1.0.0
by flashing the SD card; there is no in-place update from 5.10.

## Hardware

- Supported: the NanoKVM Lite, the Full (Cube) and the PCIe version. Only the Lite has been
  tested on hardware; the Full and PCIe support was done by review.
- Dropped: the early-access Full ("alpha", OLED at I2C address `0x3d`).

## New

- Linux 6.18.29 with the licheerv patch series and our board patches, configured from our
  own lean config, with the Sophgo media drivers ported to it.
- Boot chain from source: the FSBL from the pinned SDK, OpenSBI 1.8.1 and U-Boot 2025.10.
  The kernel, device tree and recovery initramfs come in one FIT whose hashes U-Boot checks.
- A `reboot` is an RTC warm reset, so the boot reason reads `restart`; only a real hang
  reads `watchdog`.
- TCP tuning for the video: a 16 KiB unsent threshold (`tcp_notsent_lowat`), so MJPEG frames
  do not pile up in the socket, and no slow start after an idle pause. Ethernet receive batching
  is available as an opt-in ([Files on the device](../reference/device-files.md)).
- The web UI's scripts and style sheets are sent gzip-compressed (about a third of the size)
  and cached by the browser; the package carries the compressed copies, so the device does no
  compression.
- The boot watchdog checks the server over plain HTTP on loopback, also in HTTPS mode, instead
  of a TLS handshake every 10 seconds.
- The web server encrypts with rustls only. Kernel TLS, tried during development, is not in
  this release ([why](../development/c906l-offload.md#kernel-tls-removed)).
- The server allocates memory with mimalloc instead of musl's allocator: MJPEG over HTTPS on a
  Lite went from 25.8 to 28.6 fps, about 12% less CPU per MB sent.
- MJPEG frames are read and encoded only when a viewer can take one. A stalled viewer no longer
  keeps the encoder at full rate (the device sat at 56% CPU with nothing sent), and HTTPS MJPEG
  went from 28.6 to 33.9 fps on the same Lite.
- `ethtool`, to read and set the Ethernet controller's offloads and interrupt coalescing.
- The MJPEG view stops its stream after the page has been hidden for 5 seconds and reconnects
  when it is shown again; browsers otherwise keep loading it in a background tab.

## Hardening

- No `/dev/mem` or `/dev/port`, and no `devmem` in BusyBox: media buffers are mapped through
  `/dev/cvi-sys`, which accepts only buffers the carveout handed out, and the RTC registers
  are read through nvmem.
- Signed kernel modules only, with a key each build generates and discards, and kernel
  lockdown in integrity mode.
- Memory-safety options: hardened usercopy, `FORTIFY_SOURCE`, slab freelist hardening and
  buckets, zeroing on free, list hardening, kernel stack offset randomisation and the
  stack-end check. They cost nothing measurable in MJPEG streaming; booting with zeroing on
  free turned off changed MJPEG CPU use by under 1%.
- The 5.10 kernel's hardening carries over (see [Security model](../reference/security-model.md)),
  and BSD ptys and `/proc/<pid>/pagemap` stay off as on 5.10.
- BusyBox is not setuid, and every account but root is locked, as on 0.4.0. The first
  6.x builds had missed both; the image build now checks them.

## Removed

- The 5.10 build: its workflow, Buildroot config, kernel and module scripts, and the
  vendor-SDK stock build.
- The firewall's iptables fallback: the system has only nftables.

## Known limitations

- KASLR is off: nothing passes the kernel a random seed at boot.
- The server still reads woffko's update channels ([Updates](../guide/updates.md)); the
  1.0.0 update channel is decided later.
