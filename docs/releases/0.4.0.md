# System 0.4.0 with application 2.1.0

Built on woffko's RC12 (application 2.0.42, system 0.3.0-raw.12: Buildroot
2026.05.1, Linux 5.10.265). The system version drops the `raw.N` suffix; the
update check ranks `0.4.0` above every `0.3.0-raw.N`.

## Getting it

There are no published release assets or update channels for 0.4.0 yet. Build
the image with the [CI image build](../development/ci-image-build.md) and flash
it ([Install](../guide/install.md)). The server still reads woffko's update
channels, which do not offer 0.4.0 ([Updates](../guide/updates.md)).

## Built from source in CI

- The whole SD image is rebuilt from source by a GitHub Actions workflow: vendor
  SDK, Buildroot, the Linux 5.10.265 kernel and all 57 modules, `libkvm.so`,
  `libkvm_mmf.so` and `kvm_system` from this repository's native sources, the
  Rust server, the web UI and the final image. RC12's image was built on a
  maintainer's machine, and the build no longer downloads any published Hardened
  artifact. Built from the RC10 source with the same pins, `kvm_system` matches
  the binary published in app 2.0.42 byte for byte in every code and data
  section.
- Rust 1.99.0 is pinned, and the server links with the position-independent C
  runtime objects.

## New

- **Offline updates**: signed application and system bundles can be uploaded from
  **Settings > System > Updates** once a local update key is set. An uploaded bundle is
  staged and shows as the latest version with a **Local** badge until it is installed or
  discarded ([guide](../guide/updates.md)).
- **Application update rollback**: if the new server does not answer its health check
  within about two and a half minutes, the previous application in `/root/old` comes
  back, once per update.
- **Reboot required badges**: the device name, the clock overdrive setting and an
  installed system update show a badge until the device has booted with them, and
  **Settings > Device** lists what waits beside the **Reboot** button
  ([guide](../guide/power-and-hardware.md)).
- **HTTP/HTTPS switch** restarts the server instead of rebooting the device; the new
  protocol must be kept from a signed-in browser within three minutes, or the server
  goes back to the previous protocol and firewall mode.
- **HTTPS certificate**: Tailscale or Let's Encrypt in **Settings > Network > Services**,
  renewed in the background, with confirm-or-revert and a fall back to the self-signed
  certificate ([guide](../guide/https-certificate.md)).
- **WireGuard**: a tunnel to one peer from **Settings > WireGuard**, with the
  firewall admitting the peer only on the tunnel ([guide](../guide/wireguard.md)).
- **Two-factor sign-in**: TOTP with backup codes, and a policy to require it
  ([guide](../guide/sign-in.md)).
- **HID-only mode** as a switch in **Settings > Device**, kept as a flag file.
- **Keyboard lock LEDs**: the menu bar shows the host's Num, Caps and Scroll Lock.
- **HDMI**: signal state in the API and a capture idle timeout.
- **Virtual media**: images are always mounted read-only, `/data` has one writer
  at a time, optional SHA-256 checks for uploads and downloads, download
  progress and cancel, forced eject for a locked optical drive, image sizes in the
  image list. The image and download menus are one popup: the list with mount
  and delete, and below it adding an image from a URL or a file.
- **DNS**: fixed DNS servers on a DHCP network.
- **Device name**: `h-nanokvm` on a new image (existing devices keep theirs), fully
  qualified names accepted, edited in **Settings > Device > General** with a
  **Reboot required** badge until the next boot. **Power off** sits next to **Reboot**.
- **Power menu** hidden by default on a device that looks like a Lite.
- **PicoClaw** 0.3.1, installed from its GitHub release with a pinned digest; a
  redesigned sidebar with model settings, conversation history and a live view
  of what the agent is doing ([guide](../guide/picoclaw.md)).
- **Settings redesign**: every page uses the same layout, confirmations and
  toasts; **User > Appearance** is now **User > Preferences**; the menu bar dialogs and popovers share one layout; the sign-in pages
  fit a phone.
- **Translations**: every language is one complete file, checked by a test
  against the English strings and the copy rules.
- **Web UI icons**: lucide-react 1.x; a few icons (key, trash, clock) are drawn slightly differently, and the
  forced-eject button uses lucide's own eject icon.
  The UI code no longer imports `@ant-design/icons` (spinners and the GitHub, Apple and Windows logos are lucide or inline icons); the package stays a dependency for now.
- `nano`, `picocom` and `wireguard-tools` are in the image; BusyBox `tar` handles
  gzip.

## Removed

- The preview update channels; only the stable channel is checked.
- The **Allow raw system updates** switch and its `security.allow_raw_system_updates`
  setting; the signature checks and the install confirmation remain.
- The **Confirm boot** button: the boot watchdog confirms a healthy system update by
  itself, and the confirm endpoint stays for API use.

## Ported from sipeed/NanoKVM

Zero-copy H.264 capture, one H.264 capture shared by Direct and WebRTC,
decode-driven flow control for H.264 Direct, lower latency in 60 Hz mode, WebRTC
failure notice and retry, HDMI signal and idle timeout, keyboard lock status,
read-only mounts and the `/data` handover, optional SHA-256 for downloads, the
web terminal as a root login shell, and an informative SSH prompt. Go server
changes were reimplemented in the Rust server.

## Fixes and hardening

- Changing the password requires the current password; the session lock counts
  idle time instead of time since sign-in.
- Unlocking the terminal, setting or removing the local update key, changing the
  password, disabling two-factor and reissuing backup codes ask for a fresh code when
  the account has two-factor. Wrong passwords on these actions share one lockout, apart
  from the sign-in's.
- The server refuses uploads and installs of uploaded bundles without a local update
  key.
- Turning on remote image download asks for the password and a two-factor code and is
  logged, and a download only reaches public hosts: private, loopback and local
  addresses are refused, also after a redirect.
- The page reloads after an application update when the server answers again, not
  after a fixed delay, and stays put when the update fails.
- The eth0 and USB MAC addresses and the USB serial number are derived from the
  chip ID, so they survive reflashing.
- The LT6911 chip-ID probe, which never succeeded on this board, is gone; the
  `kvm_mmf` stale-state fix and a VI state fix on fresh boots are applied.
- The health watchdog tolerates a slow server during a large image transfer.
- Commands no longer hang when a daemon they start keeps the output pipes open.
- PicoClaw no longer blocks the server while it releases the HID state, and the
  mouse fails fast when the host does not read it.
- Restricted firewall mode lets out only the tunnel's packets to the WireGuard
  peer; a stored PicoClaw key is not reused for another API server; the host name
  change rewrites `/etc/hosts` by whole name only.
- Unused OpenCV, protobuf and vendor update files are dropped from the image.

## Known limitations

- No update channels or release downloads for 0.4.0 yet.
- Translations written for this release still want review by native speakers.
