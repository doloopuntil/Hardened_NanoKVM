# System 0.4.0 with application 2.1.0

Built on woffko's RC12 (application 2.0.42, system 0.3.0-raw.12: Buildroot
2026.05.1, Linux 5.10.265). The system version drops the `raw.N` suffix; the
update check ranks `0.4.0` above every `0.3.0-raw.N`.

## Getting it

There are no published release assets or update channels for 0.4.0 yet. Build
the image with the [CI image build](../development/ci-image-build.md) and flash
it ([Install](../guide/install.md)). The server still reads woffko's update
channels, which do not offer 0.4.0 ([Updates](../guide/updates.md)).

## Built from source in CI

- The whole SD image is rebuilt from source by a GitHub Actions workflow: vendor
  SDK, Buildroot, the Linux 5.10.265 kernel and all 57 modules, `libkvm.so` and
  `libkvm_mmf.so` from this repository's native sources, the Rust server, the web
  UI and the final image. RC12's image was built on a maintainer's machine.
  `kvm_system` is the one component still taken from the published 2.0.42
  archive.
- Rust 1.99.0 is pinned, and the server links with the position-independent C
  runtime objects.

## New

- **WireGuard**: a tunnel to one peer from **Settings > WireGuard**, with the
  firewall admitting the peer only on the tunnel ([guide](../guide/wireguard.md)).
- **Two-factor sign-in**: TOTP with backup codes, and a policy to require it
  ([guide](../guide/sign-in.md)).
- **HID-only mode** as a switch in **Settings > Device**, kept as a flag file.
- **Keyboard lock LEDs**: the menu bar shows the host's Num, Caps and Scroll Lock.
- **HDMI**: signal state in the API and a capture idle timeout.
- **Virtual media**: images are always mounted read-only, `/data` has one writer
  at a time, optional SHA-256 checks for uploads and downloads, download
  progress and cancel, forced eject for a locked optical drive.
- **DNS**: fixed DNS servers on a DHCP network.
- **Host name**: fully qualified names are accepted; changing it asks whether to
  reboot.
- **Power menu** hidden by default on a device that looks like a Lite.
- **PicoClaw** 0.3.1, installed from its GitHub release with a pinned digest; a
  redesigned sidebar with model settings, conversation history and a live view
  of what the agent is doing ([guide](../guide/picoclaw.md)).
- **Settings redesign**: every page uses the same layout, confirmations and
  toasts; the menu bar dialogs and popovers share one layout; the sign-in pages
  fit a phone.
- **Translations**: every language is one complete file, checked by a test
  against the English strings and the copy rules.
- `nano`, `picocom` and `wireguard-tools` are in the image; BusyBox `tar` handles
  gzip.

## Ported from sipeed/NanoKVM

Zero-copy H.264 capture, one H.264 capture shared by Direct and WebRTC,
decode-driven flow control for H.264 Direct, lower latency in 60 Hz mode, WebRTC
failure notice and retry, HDMI signal and idle timeout, keyboard lock status,
read-only mounts and the `/data` handover, optional SHA-256 for downloads, the
web terminal as a root login shell, and an informative SSH prompt. Go server
changes were reimplemented in the Rust server.

## Fixes and hardening

- Changing the password requires the current password; the session lock counts
  idle time instead of time since sign-in.
- The eth0 and USB MAC addresses and the USB serial number are derived from the
  chip ID, so they survive reflashing.
- The LT6911 chip-ID probe, which never succeeded on this board, is gone; the
  `kvm_mmf` stale-state fix and a VI state fix on fresh boots are applied.
- The health watchdog tolerates a slow server during a large image transfer.
- Commands no longer hang when a daemon they start keeps the output pipes open.
- PicoClaw no longer blocks the server while it releases the HID state, and the
  mouse fails fast when the host does not read it.
- Restricted firewall mode lets out only the tunnel's packets to the WireGuard
  peer; a stored PicoClaw key is not reused for another API server; the host name
  change rewrites `/etc/hosts` by whole name only.
- Unused OpenCV, protobuf and vendor update files are dropped from the image.

## Known limitations

- No update channels or release downloads for 0.4.0 yet.
- Translations written for this release still want review by native speakers.
- `kvm_system` comes from the published 2.0.42 archive.
